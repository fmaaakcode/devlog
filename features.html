DevLog.

An automatic dev log for Claude Code projects. Claude writes short tags in its replies, and the Stop hook captures them to feed a local dashboard. Your history stays out of your repository, and the session-start briefing is kept small by a hard size cap.

Zero runtime dependencies Local 127.0.0.1 only No tracking Bun + Node built-ins

The main dashboard — every project's activity, plans, releases and security notes in one place.

Core

Release pipeline: checks → release → post-release

A release needs a green stamp: the project's own typecheck / lint / test, bound to the current tree and valid for 24 h. When it's missing or stale, the daemon runs the checks in the background and records the release itself once green. Then it runs the steps the project declares — mirror to a public checkout, then bun run build — and reports any failure on Claude's next turn and in doctor.

scripts/release-check.ts · release-autocheck.ts · post-release.ts · .devlog/release-check.json

Core

Asking the record

Claude pulls the past instead of re-deriving it: -(ask:search) ranks stored decisions and closed fixes against a question, -(ask:why) gives one file's dossier (purpose, decisions, every bug and how it ended), -(ask:map) ranks files by how much depends on them, and -(ask:recent) summarizes the last sessions — tags, files (shell writes included), commands and which failed.

Hidden

Retrospective, failure classes, model scorecard

Every bug and security report ever, with ages and files, and the files that keep breaking. A fix is closed with its cause and, optionally, a failure class from a fixed list (-(bug fix) #N [timing] …), so rule effects are measured against their own class. A bug that returns is linked with ⟲ and charged to the old fix. The model scorecard compares who opens bugs, whose fixes hold and who ships without a test.

GET /api/retro · /api/model-stats · /api/study · failure-class.ts

Core

Install gate · version advisor · deps page

An install without a pinned version is blocked before it runs, with the version to use: the newest stable release at least 7 days old that OSV reports clean (npm, PyPI, crates, Go). A deliberate override is recorded as an open security item. The deps page explains every library — why it's in this project, its official description and its security status.

pre-install-hook.js · GET /api/lib-advice · /api/deps · deps.html

Hidden

Project identity

Each project carries a random id in .devlog/project.json, kept out of git by a .gitignore inside .devlog/. A moved or renamed folder keeps its history, a copy becomes a new project, and two folders sharing a name never mix their records.

project-identity.ts · project-resolve.ts
